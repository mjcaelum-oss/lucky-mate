# 운세 CSV 작성 및 DB 반영

관리 파일: `C:\LuckyMate\supabase\seed\fortune_contents.csv`

CSV에는 항목별 30개씩 총 120개의 예시 콘텐츠가 들어 있습니다. 기존 행의 문구와 점수를 편집해 사용하세요. 예시도 DB에 등록되는 실제 콘텐츠이며, 주석이나 작성 안내 행은 CSV 안에 추가하지 않습니다.

## 작성 예시

```csv
id,category,message,mission,score,is_active
MONEY_01,MONEY,작은 절약이 내일의 여유를 만들어요. 오늘은 소비를 점검해보세요.,오늘 지출 한 가지를 기록해보세요.,85,true
LOVE_01,LOVE,다정한 인사가 좋은 흐름을 만들어요. 먼저 안부를 건네보세요.,고마운 사람에게 짧은 메시지를 보내세요.,90,true
WORK_01,WORK,작은 진전도 충분히 의미 있어요. 한 가지 일에 집중해보세요.,오늘의 우선순위 하나를 정해보세요.,80,true
LUCK_01,LUCK,익숙한 길에서 뜻밖의 기쁨을 발견할 수 있어요.,평소 지나치던 곳을 유심히 살펴보세요.,88,true
```

위 네 줄은 형식 예시입니다. 실제 파일에서는 전날과 다른 콘텐츠를 배정할 수 있도록 **각 항목에 활성 행을 최소 2개** 유지합니다.

| 열          | 작성 방법                                                                                      |
| ----------- | ---------------------------------------------------------------------------------------------- |
| `id`        | 기존 ID는 유지. 새 콘텐츠는 중복 없는 `MONEY_31` 등 항목 코드 + 두 자리 이상 숫자.             |
| `category`  | `MONEY` 금전 / `LOVE` 연애 / `WORK` 학업·일 / `LUCK` 행운. 기존 ID의 항목은 변경하지 않습니다. |
| `message`   | 운세 메시지. 첫 `. ` (마침표+공백) 앞 문장은 제목, 나머지는 본문으로 표시합니다.               |
| `mission`   | 사용자가 할 수 있는 행운 미션. 빈 값 불가.                                                     |
| `score`     | 0~100 정수. 선택된 콘텐츠와 함께 표시하는 고정 점수.                                           |
| `is_active` | `true` 배정 가능 / `false` 신규 배정 제외. Excel의 `TRUE`, `FALSE`도 허용.                     |

이 CSV는 Excel에서도 한글을 식별할 수 있도록 **UTF-8 BOM**으로 저장되어 있습니다. Excel에서 편집했다면 **CSV UTF-8(쉼표로 분리)**로 저장하세요. VS Code에서는 저장 인코딩을 **UTF-8 with BOM**으로 선택하세요. 일반 CSV/ANSI로 저장하면 한글이 깨질 수 있습니다. 이미 열어 둔 파일은 저장하지 말고 닫은 뒤 다시 여세요.

헤더와 순서를 유지합니다. 직접 편집할 때 쉼표나 줄바꿈을 포함한 셀은 큰따옴표로 감싸고, 셀 안의 큰따옴표는 두 번 씁니다: `"오늘은 ""작은 변화""를, 시도해보세요."`.

## 반영 방법

프로젝트 폴더 `C:\LuckyMate`에서 실행합니다.

```powershell
# 검증만: DB를 변경하지 않음
rtk proxy npm run content:check

# 검증 후 .env.local에 연결된 Supabase DB에 일괄 반영
rtk proxy npm run content:sync
```

`.env.local`의 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`를 사용합니다. 기존 `SUPABASE_SERVICE_ROLE_KEY`도 지원합니다. 실행 전 대상 프로젝트 주소를 확인하세요. 파일 저장만으로 DB가 변경되지는 않으며, `content:sync`가 반영 명령입니다.

같은 ID는 메시지·미션·점수·활성값을 갱신하고 새 ID는 추가합니다. CSV에 없는 기존 행은 삭제하거나 비활성화하지 않습니다. 사용을 중단할 콘텐츠는 행을 유지하고 `is_active=false`로 바꾸세요. CSV 전체 검증을 통과한 후 한 번의 DB 요청으로 반영하며 DB 오류가 나면 그 요청은 부분 적용되지 않습니다. 통신 실패는 처리 결과가 불명확할 수 있으므로 연결 복구 후 같은 파일로 다시 실행하세요.

이미 발급한 결과와 과거 공유 링크도 다음 조회부터 수정된 문구·미션·점수를 보여줍니다. 날짜·숫자·컬러는 유지됩니다. DB 반영에 Vercel 재배포는 필요 없습니다. 이미 열린 화면은 다시 조회해야 새 내용이 보입니다.

`rtk proxy npm run seed`는 CSV로부터 `supabase/seed.sql`만 생성합니다. CSV를 덮어쓰거나 DB를 변경하지 않습니다. SQL Editor에서 생성된 SQL을 직접 적용하는 것도 가능합니다. 로컬 데모 모드의 콘텐츠는 기존 `lib/content.ts` 초안을 사용하므로 DB 반영 확인에는 Supabase 연결 모드를 사용하세요.
