# 럭키메이트 개발계획

기준: PRD v1.0 (2026-10-01), 제공한 모바일 디자인. 문서는 제품 요구사항 자료로 사용하며, 실행 권한은 사용자의 개발 및 배포 요청을 기준으로 한다.

## 확정 사항

- Next.js App Router + TypeScript + React, Vercel 배포.
- Supabase PostgreSQL. Auth 사용하지 않음. 모든 DB 요청은 서버 API 경유.
- 100개 키링 FC001~FC100. 서버에서 활성 여부 확인.
- 한국시간 기준 일일 결과. 키링 행 잠금 + unique 제약으로 동시 최초 요청 직렬화.
- 콘텐츠 30개 × 4개 분야. 전날 배정 콘텐츠 제외. 기존 결과는 현재 콘텐츠 본문 참조.
- 128비트 UUID 기반 공유 토큰. 결과당 하나 재사용, 원래 날짜 유지.
- 확인 완료 상태는 키링·날짜별 localStorage. 결과 자체는 서버 저장.
- 구매 URL 미정: 준비 중 안내. 새 Supabase/Vercel 프로젝트 사용.

## 개발 순서 및 수용 기준

| 단계 | 작업                                             | 검증                                                   |
| ---- | ------------------------------------------------ | ------------------------------------------------------ |
| 1    | 모바일 6개 주요 화면, 오류·안내 화면, 클로버 SVG | 모바일/데스크톱 확인, 모든 CTA 동작                    |
| 2    | Supabase 테이블, RLS, 서비스 역할 전용 RPC, CSV  | 100개 키링/120개 콘텐츠, API 비밀키 비노출             |

## 구현 상태와 남은 작업

화면, API, DB 마이그레이션, 초안 콘텐츠, 로컬 개발 저장소를 구현했다. 로컬 저장소는 화면 및 API 검증용이며 Vercel에서는 강제로 비활성화한다. 실제 계정 인증 및 새 프로젝트 생성은 별도 단계로, 로컬 미리보기 결과가 운영 DB 검증을 대체하지 않는다.

운영 전에는 초안 콘텐츠 120개 문안을 검토하고, 실제 Supabase에서 동시 요청/비활성 키링/본문 수정/자정 경계 테스트를 수행한다. 구매 URL과 production 도메인은 배포 후 확정한다. IP/기기 식별정보는 이벤트에 저장하지 않는다.

2026-10-08 후속 요청으로 실제 Supabase/Vercel 연동을 시작했다. 서버의 새 Supabase 비밀키 및 기존 service_role JWT 지원, 실제 배포 주소용 API 검증 명령 준비와 로컬 검증을 마쳤다. 아직 계정 플러그인/CLI 인증 및 대상 프로젝트가 확인되지 않아 외부 DB 적용과 배포는 진행되지 않았다. 계정 연결 후 기존 프로젝트 상태와 무료 프로젝트 생성 한도를 확인한다.

## 분석

Raw NFC 이벤트를 모두 보존한다. `supabase/analytics.sql`은 5분 이내 연속 NFC 진입을 한 세션으로 집계하며, 활성화율·7일 재접속·분야 선택·공유 전환 조회를 제공한다. 공개 API이므로 로그는 클라이언트 위조 가능성이 있는 제품 분석 자료다. 운영 시 Vercel Firewall의 기본 봇 보호와 API 속도 제한을 설정한다.

## 디자인

그린/민트, 둥근 카드, 분홍 연애 배지, 네 잎 선택의 배치와 결과 정보 위계를 반영한다. SVG 클로버는 구현용 자체 제작 그래픽이며 원본 3D 에셋 제공 시 교체 가능하다. 움직임 줄이기 설정을 지원한다. 데스크톱에는 브랜드 소개를 함께 표시한다.
